## Context: what this engine is

The engine's central idea is that the world is a log. Nothing has mutable state. Events arrive, accumulate in an append-only log, and all derived state is computed from that history on demand. The log is never modified — facts are never retracted, never overwritten.

This session builds the log and clock: the two foundational data structures everything else reads from. Nothing else can be tested until these exist.

## Specification

### `engine/log.pl`

#### `arrived/5`

```prolog
:- dynamic arrived/5.
% arrived(EventId, Scene, Term, Clock, Tier)
```

The central dynamic fact. All five arguments are always present on every asserted fact.

- `EventId` — a unique atom generated by `fresh_event_id/1` (see below). Format: `evt_N` where N is a monotonically increasing integer starting at 1.
- `Scene` — an atom naming the scene this event arrived in.
- `Term` — any Prolog term. This is the event content.
- `Clock` — an integer. The clock value at the time of arrival.
- `Tier` — one of the atoms `hot`, `cold`, `archived`. Always `hot` on initial arrival.

#### `arrived_key/4`

```prolog
:- dynamic arrived_key/4.
% arrived_key(Scene, Term, Clock, EventId)
```

Deduplication index. Asserted alongside every `arrived/5` fact. Before asserting a new arrived fact, check whether `arrived_key(Scene, Term, Clock, _)` already exists. If it does, skip — do not assert a duplicate. The event that would have been a duplicate is silently discarded.

#### `tier_status/2`

```prolog
:- dynamic tier_status/2.
% tier_status(EventId, Tier)
```

The current tier of each event. Asserted on arrival as `hot`. When a tier changes, a new `tier_status` fact is asserted — the old one is retracted. This is the only retraction allowed in `log.pl`. The `arrived/5` fact itself is never retracted.

**Important:** `tier_status/2` is a single-valued index: at any moment there is exactly one `tier_status` fact per `EventId`. Updating it requires retracting the old value and asserting the new one. This controlled retraction of `tier_status` does not violate the append-only guarantee, which applies to `arrived/5`.

#### `tier_transition/4`

```prolog
:- dynamic tier_transition/4.
% tier_transition(EventId, FromTier, ToTier, Clock)
```

Audit log of all tier changes. Always appended, never retracted.

#### `inject_event/3`

```prolog
inject_event(Scene, Term, Cause) :-
    ...
```

The single entry point for adding events to the log. All event insertion goes through this predicate. It must:

1. Read the current clock value via `clock_value/1`.
2. Check `arrived_key(Scene, Term, Clock, _)`. If found, succeed without asserting anything (idempotent).
3. If not found: call `fresh_event_id(EventId)` to generate a new ID.
4. Assert `arrived(EventId, Scene, Term, Clock, hot)`.
5. Assert `arrived_key(Scene, Term, Clock, EventId)`.
6. Assert `tier_status(EventId, hot)`.
7. Assert `caused_by(EventId, Cause)`.

Note: `caused_by/2` is declared in `engine/provenance.pl` (Session 2). For this session, declare it as a dynamic fact here temporarily so `inject_event/3` can assert it. Session 2 will move the declaration and you will remove the temporary one. Document this with a comment.

#### `fresh_event_id/1`

```prolog
:- dynamic event_counter/1.
event_counter(0).

fresh_event_id(EventId) :-
    retract(event_counter(N)),
    N1 is N + 1,
    assertz(event_counter(N1)),
    atom_concat(evt_, N1, EventId).
```

Monotonic counter. Retract-and-reassert of `event_counter/1` is acceptable here — it is an internal counter, not a log fact.

#### `hot_events/1`

```prolog
hot_events(Events) :-
    findall(EventId, tier_status(EventId, hot), Events).
```

Convenience predicate used by the fixpoint (Session 4).

#### `log_count/1`

```prolog
log_count(N) :-
    aggregate_all(count, arrived(_, _, _, _, _), N).
```

Used by `verify/invariants.pl` and tests to check that the log only grows.

### `engine/clock.pl`

```prolog
:- dynamic clock_counter/1.
clock_counter(0).
```

The world's single clock. One dynamic fact, always present.

#### `clock_value/1`

```prolog
clock_value(V) :- clock_counter(V).
```

#### `advance_clock/0`

```prolog
advance_clock :-
    retract(clock_counter(N)),
    N1 is N + 1,
    assertz(clock_counter(N1)).
```

The only place in the engine where `clock_counter` is retracted. This retraction is acceptable — the clock counter is not a log fact. `arrived/5` is never retracted.

### `tests/log_tests.pl`

Write tests using SWI-Prolog's `plunit` library.

```prolog
:- use_module(library(plunit)).
:- use_module('../engine/log').
:- use_module('../engine/clock').
```

**Required test cases:**

**T1 — Basic injection**
Inject one event. Assert that exactly one `arrived/5` fact exists with the correct Scene, Term, Clock, and Tier = `hot`. Assert that one `tier_status(EventId, hot)` fact exists. Assert that one `arrived_key` fact exists.

**T2 — Deduplication**
Inject the same `(Scene, Term)` at the same clock value twice. Assert that exactly one `arrived/5` fact exists (not two). The second call to `inject_event` must succeed without error and without creating a duplicate.

**T3 — Clock value stamps events correctly**
Advance the clock twice. Inject an event. Assert that the `arrived` fact carries the current clock value (2), not 0 or 1.

**T4 — Log is append-only**
Inject three events. Assert `log_count(3)`. Manually attempt to run any normal sequence of operations (advance clock, inject more events). Assert the count never decreases. Do not attempt to retract `arrived` directly — test that the count only grows.

**T5 — Tier status initialises as hot**
Inject an event. Assert `tier_status(EventId, hot)` holds for the generated EventId.

**T6 — Tier transition audit**
Manually assert a `tier_transition` fact (simulating what lifecycle/tiers.pl will do in Session 6). Assert it is readable. Assert that asserting a second transition for the same EventId produces two `tier_transition` facts (the audit log is append-only, both coexist).

**T7 — Clock advances correctly**
Call `clock_value(V0)`. Call `advance_clock` three times. Call `clock_value(V1)`. Assert `V1 =:= V0 + 3`.

**T8 — EventId uniqueness**
Inject five events (different terms or scenes). Collect all EventIds via `findall`. Assert the list has no duplicates.

**T9 — caused_by is asserted**
Inject an event with `Cause = injected(player)`. Assert that `caused_by(EventId, injected(player))` holds for the generated EventId.

**Test isolation:** Each test must start from a clean state. Use `setup_call_cleanup` or a `setup` block that retracts all dynamic facts and resets counters before each test. A helper predicate `reset_log` should:
- Retract all `arrived/5` facts
- Retract all `arrived_key/4` facts
- Retract all `tier_status/2` facts
- Retract all `tier_transition/4` facts
- Retract all `caused_by/2` facts
- Retract `event_counter(_)` and assert `event_counter(0)`
- Retract `clock_counter(_)` and assert `clock_counter(0)`

## Design decisions in force for this session

These come from the implementation plan. Do not re-derive or second-guess them.

**D1 — Event identity.** Use a monotonically assigned `EventId` atom (`evt_N`) as the canonical identity handle. A separate `arrived_key/4` index handles deduplication. Identity and deduplication are separate.

**D2 — Clock retraction.** `clock_counter/1` is retracted and reasserted in `advance_clock/0`. This is the only place a log-adjacent fact is retracted. `arrived/5` is never retracted.

**D12 — Tier promotion mechanics.** `tier_status(EventId, Tier)` is a separate index fact. Tier transitions are recorded as `tier_transition` facts. Updating `tier_status` requires retracting the old value and asserting the new one — this is acceptable because `tier_status` is an index, not a log fact. The `arrived/5` fact itself is never retracted.
